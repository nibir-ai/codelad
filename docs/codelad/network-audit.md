# Reproducible desktop network audit

Run after native dependencies, the exact configured Electron runtime and the client/built-in extensions have been built. Raw capture belongs under ignored `.build/codelad/`, never in Git. Review locally before sharing: even Default NetLog capture can contain private paths, URLs and request metadata. Do not enable `IncludeSensitive` or `Everything` capture modes.

## Capture procedure

1. Verify source and final packaged product metadata: `node build/codelad/check-privacy.ts` and `node build/codelad/check-privacy.ts <packaged-product.json>`. Save version, commit, host, command and result with the audit. These checks do not replace network observation.
2. On the host platform, start a process-scoped OS socket/packet/DNS capture using an available trusted capture tool. Track the editor process and all descendants, including extension host, shared process, crash handler, Git, shells and language servers. Capture loopback separately. Chromium NetLog alone cannot observe Node or native subprocess traffic.
3. Launch the development build with a fresh isolated profile: `node scripts/codelad/network-audit.mts --workspace <local-fixture-folder>`. Use `--executable <absolute-path-to-executable>` if the development binary is elsewhere. For a packaged binary, add `--packaged --executable <absolute-path-to-packaged-binary>`; this omits the development entrypoint and clears inherited `VSCODE_DEV`. The helper refuses to reuse an existing output directory. It isolates user, extensions and shared-data directories, preserves Workspace Trust and disables installed extensions for the core baseline. On Windows it also starts a hidden process-tree TCP sampler; on Linux it starts the `/proc` plus `ss -Htanup` TCP/UDP sampler writing `connections.jsonl`. The default capture duration is three minutes; choose 1–3600 seconds with `--duration-seconds`. Ensure that duration covers shutdown. This sampling can miss short-lived connections, startup races and unconnected UDP/DNS, so retain the independent OS capture for stronger coverage.
4. Record timestamps for each action in a local notes file. Idle for two minutes, open local text/source, edit/save/search, open a local Git diff, run terminal, run an explicitly inspected harmless task, resize, restart and close normally. Use a non-secret fixture with a disposable local Git repository. Record actual observed process behavior and failures.
5. Close the editor normally to flush NetLog. Summarize a completed log with `node scripts/codelad/network-audit.mts --summarize <netlog.json>`. Hostnames and counts are printed; paths, queries, credentials and headers are omitted. A nonzero exit indicates a host was not explicitly expected for this action, not proof it is telemetry. An empty host list is not proof no traffic occurred.
6. In a separate fresh run, explicitly browse/install an OSS extension. Record the chosen extension, manifest/license, exact gallery request and redirect hosts. Classify every host; only then use `--allow-host open-vsx.org` (repeat the option for individually reviewed asset hosts) to compare against the action's expected destinations. An allowlisted host is not a guarantee that all request payloads are benign.
7. Separately test built-in extensions and selected third-party extensions. The helper's baseline uses `--disable-extensions`; repeat with `--enable-extensions` and a separate fresh output directory to omit that switch. Built-in activation still follows its normal trust/language gates, and the isolated extensions directory starts empty. Attribute traffic with OS process capture and local logs, never by assuming all editor-owned connections originate in core services.
8. Test crashes in a disposable process/profile only: request a local dump directory, trigger a native renderer crash through test tooling, and confirm that no crash upload occurs in both Chromium and OS captures. Test modified `argv.json` attempting to enable crash uploads; the product guard must still win. Preserve crash evidence locally because dumps may contain sensitive memory.
9. Disconnect network and repeat editing, search, terminal, local Git, tasks and language diagnostics. Distinguish features that require a user-selected external service from local regressions.

## Required report

Record editor version/revision, product metadata check, OS/runtime, extensions, profile freshness, capture tools/coverage, each action/time, process/host/category, payload review outcome, pass/fail and limitations. Unexpected destinations must be explained or fixed before claiming Phase 1 accepted. Verify shutdown traffic and child processes remaining after the window closes.

The launcher writes `capture.json` at launch and updates it only after both the desktop and sampler have finished, recording their exit codes/signals. A sampler failure makes the launcher's result nonzero even when the desktop exits successfully. On POSIX, the output directory is mode 0700 and metadata is mode 0600. An optional `--remote-debugging-port 0` enables loopback CDP automation; read the selected port from `profile/DevToolsActivePort`. Leave that option out of ordinary captures. The helper removes inherited Electron run-as-Node and indexed Git configuration switches from the desktop environment, without copying an authenticated profile or disabling Workspace Trust.

For a disposable native crash scenario, add `--local-crash-dumps`. This passes an explicit absolute dump directory under the private audit output, records the option in metadata and preserves the product's no-upload policy. It is off in ordinary captures. A dump may contain memory: keep it local and review before sharing. See [Linux crash recovery](linux-crash-recovery.md) for actual native Reopen/shutdown evidence, IPC fixes and capture limits. Use an isolated desktop for native dialogs; verify the exact test window before taking a native screenshot or sending input. Playwright cannot drive an OS dialog through the renderer DOM.

Historical Windows evidence: five desktop runs are described in [phase-1-report.md](phase-1-report.md), with the latest test totals in [HANDOFF.md](HANDOFF.md). The final run installed an Open VSX extension and observed registry/content hosts, including requests before explicit browsing whose caller remains unattributed. Raw captures stayed on the original Windows host and are not in this Linux checkout. The earlier baseline prerequisite failures do not mean those later captures never occurred. No complete runtime or packaged privacy acceptance is claimed.

Linux continuation (2026-10-29): actual development and packaged captures now exist. The native-session dictionary fix removed observed Google dictionary traffic in a fresh Linux run. Before explicit extension browsing, 207 socket samples observed no nonloopback connections and Chromium listed no URL hosts; subsequent YAML installation used Open VSX/Eclipse assets and README images. The historical Windows startup registry caller remains unattributed. Packaged local coding was additionally tested in a user/network namespace with loopback only; host networking was untouched. ## Linux sampler

```bash
node scripts/codelad/capture-linux-connections.mts --root-pid <editor-pid> --output <new-jsonl-file> --duration-seconds 180
```

Requires Linux `ss` (iproute2) and readable `/proc` entries. The helper follows children of all task threads, checks process start times for PID reuse, retains live discovered descendants after the root exits, and records only editor-owned numeric endpoints/state/PID. Zombies are treated as exited. Output is created exclusively with mode 0600. Failed capture commands, unreadable process entries, unparsed owned rows and interruption cause a nonzero result. Treat any such issue as incomplete coverage. It does not retain command arguments or process names, but numeric endpoints still need review before sharing.

The final JSONL record reports `finished`, `reason`, `remainingProcessCount` and `incomplete`. `process-tree-exited` with zero remaining processes records completion of the discovered tree. `duration-limit` records a timed sample and can exit successfully with live processes remaining; it does not establish shutdown coverage. `interrupted` and `capture-error` record incomplete captures. Previously the sampler stopped as soon as the root exited and could miss a child's shutdown traffic; earlier captures retain that limitation. Seven real-process regression tests now cover an orphaned child with a UDP socket, timed completion, interruption, command failure, output preservation, development/packaged argument and environment isolation, and propagation of sampler failure through the launcher.

One-second snapshots can miss sockets/processes between samples, connections established before sampler startup, unconnected UDP/DNS or inaccessible process owners. NetLog omits Node/native transports; an empty report from either helper is not proof no traffic occurred. Use independent packet/DNS/process instrumentation for stronger acceptance. The default launcher disables installed extensions for a core baseline; a built-in-enabled or third-party action needs a separately isolated run.

## Offline Linux packet capture

The optional [packet helper](../../scripts/codelad/capture-linux-packets.py) uses Python's standard library plus installed `unshare` and `ip`; it does not need tcpdump or host capture privileges. It creates new user, network, PID and mount namespaces, mounts private `/proc`, verifies that only loopback exists and starts the packet socket before executing the specified command. Host interfaces/routes remain unchanged. This is offline capture, not an online allowlist or firewall verdict. File access is not isolated: use inspected commands and disposable fixtures.

```bash
# Positive IPv4/IPv6 DNS, TCP and lifecycle/coverage controls.
python3 build/codelad/linuxPackets.test.py -v

# Harmless packet control on the disposable namespace's loopback.
python3 scripts/codelad/capture-linux-packets.py \
  --output .build/codelad/packet-control \
  -- python3 -c 'import socket; s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM); s.sendto(b"codelad-control",("127.0.0.1",55353)); s.close()'
```

Replace the command after `--` with an inspected local scenario to capture its whole namespace. The output directory must be new and is mode 0700; `packets.pcap` and `capture.json` are mode 0600. Raw packets include payloads and can expose code, paths, tokens or automation messages; keep them ignored/local and review before sharing. Command arguments, environment variables, payloads and DNS names are not copied into the metadata. Command stdout/stderr remain the caller's responsibility.

Defaults are 180 seconds, 128 MiB and a 262144-byte snapshot length. `--duration-seconds`, `--max-bytes` and `--snaplen` set explicit bounds. The helper retains namespace children after the command exits, reaps orphans and drains packets for one further second once all children have exited. Private background services must be shut down by the scenario after the editor quits; otherwise reaching the deadline correctly marks the capture incomplete. Time/size limits terminate only the disposable process namespace. Losing the parent, interruption, child network-namespace changes, unreadable process state, dropped/truncated frames or unrecorded kernel packets cannot produce a complete result. There is no host-capture fallback when namespace setup is unavailable.

Accept a result only with `status:finished`, `captureComplete:true`, zero drops/truncation/unrecorded packets, zero remaining processes and the expected command exit code. A fully captured command that exits 17 still returns 17; capture completeness does not mean the scenario passed. Interrupted output can be partial even if it has a valid PCAP prefix. `capture.json` is finalized at completion; its startup counters are not a live readout.

The file uses the [libpcap savefile format](https://man7.org/linux/man-pages/man5/pcap-savefile.5.html), Ethernet link type 1 and microsecond receipt timestamps. Linux loopback includes outgoing/incoming copies, so frames are not requests. [Packet-socket statistics](https://man7.org/linux/man-pages/man7/packet.7.html) supply the kernel packet/drop counters; a complete capture requires the reported packet total to equal recorded frames. Positive controls and the actual packaged run were also read independently through the installed libpcap library. See [offline packet report](linux-packet-audit.md) for the actual DNS controls, editor actions and first failed attempt.

This cannot observe requests blocked before a packet exists, Unix-domain traffic, activity delegated to services outside the namespace, encrypted payload meaning or online behavior. It records frames rather than per-process causality; pair it with socket samples, Chromium logs and action timestamps. CDP automation must run inside the network namespace because its loopback endpoint is unavailable outside it. Namespace-root Electron needs the documented test-only `--no-sandbox` flag; this does not change shipping defaults or validate the shipping sandbox. Use a separate virtual desktop for the scenario rather than the user's foreground session.
