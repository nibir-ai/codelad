# Native material evidence, Windows development process

Scope: Windows 11 25H2 build 26200.9168, Electron 43.8.3, source workbench, isolated user/shared/extension directories. No personal credentials or third-party extensions were copied. The temporary extension changes only its disposable user settings and fixture files and invokes existing editor/terminal commands.

[Runtime results](runtime-results.json) record ten material/layout states, computed chrome/editor/terminal backgrounds, viewport sizes and read-only DWM attribute 38 results. DWM values 3, 2 and 1 identify Acrylic, Mica and no backdrop. The extra reading-surface sample confirms an opaque `rgb(25, 26, 27)` terminal panel, opaque `rgb(18, 19, 20)` editor and live chrome alpha 0.85. A transparent terminal wrapper is expected; its enclosing panel retains the opaque reading background. These are tested theme values, not a guarantee about arbitrary user-authored theme colors. Whole-window opacity is 1 and maximize/restore returns normally.

The saved edit is independently read from disk; split editor containers and the terminal wrapper are asserted. This confirms opening a real terminal, not the correctness of arbitrary shell workflows. The fixture reports telemetry disabled. It introduces no external endpoint and does not repeat the earlier notebook/provider payload audit.

The final editor and extension host exit normally with code 0. The [completed Chromium summary](shutdown-network-summary.json) contains no URL hosts or empty WebSocket events. This is Chromium-only coverage; Node/native traffic, DNS and OS-level offline behavior remain outside this capture.

Raw build/type/lint/test logs and isolated profiles remain ignored under `.build/codelad/native-glass-poc-2026-10-30/`. Temporary executable helpers are removed after the run. Early attempts are not passes: one fixture control read its response before the file existed; a retry reused an externally overwritten document and encountered a save conflict; one editor launch preceded completion of the clean transpile. A cold extension-host startup exceeded the fixture wait and recovered; the development theme contribution initially selected its high-contrast fixture; a repeated terminal run matched a hidden older wrapper. The final run selects its starting theme explicitly, uses fresh save paths and targets the visible terminal after the completed build. A startup network-service restart and recovered extension-host watchdog are retained in raw development logs, not attributed to the glass adapter without further evidence. Native captures disturbed by foreground activity were discarded. No live-background screenshot, benchmark, OS-offline result or cross-platform acceptance is claimed.
